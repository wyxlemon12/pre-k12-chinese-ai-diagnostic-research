# 教师视角体验记录

这份记录基于一次“非技术教师”视角的主观体验回放，目标不是评估代码质量，而是判断这个界面会不会让一线老师愿意继续用下去。

## 最强正向信号

- “生成本课三件套”这个按钮命名非常好，老师一眼就知道点下去会得到什么。
- 整个页面更像一个工作台，而不是一个随便拼出来的 AI demo。
- 如果输出内容真的能直接拿去上课，老师会愿意把它当作备课辅助工具反复使用。

## 最强负向信号

- 一旦页面出现 `API 状态`、`Failed to fetch`、`HTTP 404` 这类技术语言，非技术教师会立刻退缩。
- 第一次进入页面时，老师还不够确定“到底要先填哪些内容，才能放心点生成”。
- `能力路径卡`、`诊断`、`证据链` 这些词虽然专业，但需要再贴近课堂动作，不然会被理解成抽象术语。

## 最接近真实心声的一句话

“看起来很像是能帮我把备课从凭经验瞎想，变成有步骤可落地；但只要它一提示技术错误，我就会立刻觉得这不是给我用的。”

## 对产品方向的启发

这轮反馈说明产品方向是对的，但界面语言要更像教师助手，而不是工程验证台。

接下来最值得优先处理的不是增加更多花哨功能，而是：

1. 把报错文案翻译成教师能理解的语言
2. 把首屏步骤提示写得更明确
3. 让每个输出区域都对应一个清晰的课堂动作

## 建议下一轮优化

1. 把 `API 状态` 改成更产品化的表达，例如“课堂助手连接中 / 已准备好 / 暂时没连上”。
2. 在输入区上方补一句 10 秒内能看懂的引导，例如“先贴入 4-6 句短文本，再点生成本课三件套”。
3. 把 `能力路径卡` 改写成更贴近教学动作的名字，例如“起步支持组 / 标准任务组 / 延展表达组”。
4. 把 `证据链诊断` 的输出标题改成“我现在最该先补什么”，减少术语负担。
