老师后台 UI 方向对比

这三版都借可汗学院老师后台的秩序感、可信度和任务导向，但强调点不同。你这次的产品不是学生学习页，而是 “老师备课与带课的工作台”。

Khan 风格来源：左侧导航、清晰卡片、轻运营仪表盘
产品不变：老师主导，AI 幕后编排
首个 demo：10 分钟微课包

A. Dashboard First

最像可汗老师首页。先看到班级、学生、最近微课包和待办，再进入具体编辑。

可信
管理感强
适合讲“平台”故事

代价是主任务会多一步，首次 demo 容易看起来像后台系统，而不是一套能直接上课的工具。

B. Studio First

左侧是可汗式稳定导航，中间是“当前微课包”主工作区，右侧是 AI 生成的老师动作卡。

推荐
主任务最清楚
像老师工作台

最适合这个 demo。既保留后台秩序感，又把“生成、确认、带课、回收反馈”串成一个连续工作流。

C. Runtime First

把“上课时正在发生什么”放到最中心，适合强调课堂运行、实时支架和观察信号的切换。

课堂感强
演示冲击力大
适合现场讲故事

缺点是备课、课后回写、学生记录会显得像附属页，不利于展示你完整的产品设计能力。

我建议选 B 的原因
  • 最贴合“老师主导、AI 幕后”的产品逻辑。
  • 最容易把微课包做成一个真正的核心对象，而不是一堆页面。
  • 既像成熟教育产品，又能保留你要展示的课程设计能力。
如果你更重面试观感
  • A 会更像完整 SaaS 后台。
  • B 会更像有方法论的教学工作台。
  • C 会更像“现场可跑”的课堂控制系统。
这轮请你判断
  • 哪一版最像你想要的可汗老师后台气质。
  • 你更想让面试官先看到管理能力，还是先看到教学工作流。
  • 如果选 B，我下一轮就把它细化成页面结构和组件层级。
