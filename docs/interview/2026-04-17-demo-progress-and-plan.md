# 六岁中文微课 Demo 进度与后续计划

## 1. 文档目的

这份文档用于记录当前仓库内已经完成的工作、已经明确但尚未实现的设计决策，以及接下来一到两轮开发最值得优先推进的事项。

它服务于两个场景：

1. 面试展示前快速对齐当前 demo 到了什么程度。
2. GitHub 留痕，避免后续把“已完成”和“仍在设计中”的内容混在一起。

---

## 2. 当前项目定位

当前 demo 的产品定位已经收敛为：

`老师主导、AI 幕后编排的六岁启蒙探究型中文微课工作台`

首个固定场景为：

- 年龄：`6岁`
- 时长：`10分钟`
- 主题：`节日食物`
- 核心问题：`为什么有些食物会在特别的日子吃？`

本 demo 当前不追求生产级系统完整度，而是优先展示：

- 课程设计能力
- 动态分层能力
- 教师工作流理解
- 面试现场可讲清楚、可跑通的完整体验

## 3. 已完成进度

### 3.1 产品与范围层

以下关键判断已经明确并写入现有文档：

- 已形成一份独立的面试展示型 PRD：
  - [2026-04-17-isf-ckstem-demo-prd.md](/W:/Project/05%20-%20Education/pre-k12-chinese-ai-diagnostic-research/docs/interview/2026-04-17-isf-ckstem-demo-prd.md)
- 已明确产品不是学生自由创作型 AI 工具，而是：
  - 教师备课与带课工具
  - 课堂中 AI 不抢教师主导权
  - 个性化反馈通过教师端轻量学生卡片承接
- 已明确主流程围绕 `MicroLessonPackage` 展开，而不是零散分析页。

### 3.2 后端能力层

目前后端已经具备可跑通的微课工作流原型：

- 支持创建微课草案 `draft`
- 支持确认微课包 `confirm`
- 支持课堂中根据观察信号返回支架建议 `classroom-signal`
- 支持课后反思并回写学生卡片 `reflect`
- 支持列出与获取微课包

当前数据结构已覆盖：

- source materials
- hook
- core question
- language goals
- focus support
- time blocks
- scaffold paths
- observation signals
- teacher prompt cards
- student cards
- reflection summary
- next lesson moves

### 3.3 前端体验层

当前 web 端已经具备一个可运行的教师工作流原型，包含以下主视图：

- 编辑视图
- 课堂运行
- 课后反馈
- 学生记录
- 扩展工具

已经完成的关键交互修复包括：

- 切换不同微课包时，编辑区状态会同步刷新，不再保留上一份包的残留内容。
- 课堂运行中应用观察信号后，学生选择会自动清空，避免连续误操作。
- 课后反馈可以基于课堂日志生成摘要，并把结果回写到学生卡片。

### 3.4 内容生成与分层逻辑

目前已完成一版可演示的规则化内容生成逻辑：

- 能从主题和素材中抽取焦点词
- 能生成 4 段式 10 分钟微课结构
- 能生成 3 条支架路径：
  - 图片支持路
  - 句框短句路
  - 原因表达路
- 能生成 5 个高价值课堂观察信号

并且已经修复了主题词抽取偏泛化的问题：

- 当主题切换到 `端午为什么吃粽子` 时，焦点词会正确落到 `粽子 / 龙舟 / 端午`
- 不再错误沿用默认的 `月饼`

### 3.5 测试与验证层

当前仓库内已经补上了一组针对微课闭环的测试：

- API 工作流测试
- 前端状态工具测试

此前已通过的验证包括：

- web vitest

- Vite build

此外，已经做过一次“非技术教师视角”的体验回放，结论已记录在：

## 4. 已确定但尚未落代码的内容

以下内容已经完成方向判断，但还没有进入正式实现：

### 4.1 Studio First UI 改版

`B. Studio First`

它的核心结构是：

- 左侧：稳定的老师后台导航

这个方向借鉴的是可汗学院老师后台的：

- 秩序感
- 可信度
- 任务导向

而不是学生学习页的视觉语言。

## 5. 当前仍存在的缺口

### 5.1 UI 还不够像成熟教学产品

虽然当前流程能跑，但视觉上仍更接近早期原型，而不是高可信度的老师工作台。

面试场景里，这会直接影响第一印象。

### 5.2 首屏引导还不够短平快

老师第一次进入时，仍需要更清楚地知道：

- 先填什么
- 点哪个按钮
- 生成后会得到什么

### 5.3 课堂运行页仍需进一步收束

产品逻辑已经明确：

- 课堂中 AI 不应主导发声
- 不应做一人一机实时口语互动

但页面还需要更强地体现：

- 老师在带课
- 系统只是在旁边给动作建议

## 6. 下一步计划

### 6.1 第一优先级：UI 结构重做

按 `Studio First` 改造主界面：

- 重做页面骨架
- 引入可汗式老师后台的导航与卡片层级
- 把当前微课包做成绝对主视觉中心
- 固定右侧老师助手区

目标：

让面试官第一眼看到的不是“AI 表单”，而是“教学工作台”。

### 6.2 第二优先级：产品化语言统一

统一以下文案层：

- 页面标题
- 操作按钮
- 空状态
- 连接状态
- 错误提示
- 输出区标题

目标：

让非技术教师在第一次使用时也不会因为术语和报错而退缩。

### 6.3 第三优先级：跑通一节真实微课

固定一个真实案例，完整走通：

1. 输入素材
2. 生成微课包
3. 确认 hook 与核心问题
4. 进入课堂运行
5. 点选观察信号
6. 生成课后反馈
7. 回写学生卡片

目标：

让 demo 不是“看起来像能用”，而是“真的能完整演示一次”。

### 6.4 第四优先级：面试展示辅助材料

在主 demo 稳定后，再补：

- 1 页展示脚本
- 1 页产品亮点摘要
- 1 页为什么这个方案适合弘立 / CK STEM

目标：

让产品判断、教育理解和执行能力在面试现场被更容易看见。
